# ТТН по списку СФ — «0.2.0»

Локальное приложение для XLSX/CSV и API Didox/Smartup: поиск СФ и заказа,
просмотр ТТН, создание выбранных черновиков, PDF, отчёт и отдельное подписание
через E-IMZO. Поддерживаются одна СФ и выбранный пакет с результатом по каждой строке.

**Код проверен на локальном имитаторе официальных API, но не на аккаунтах
заказчика. Официальную привязку новой ТТН к уже подписанной СФ нужно подтвердить
в Didox: текущая программа хранит связь в своём журнале и не изменяет исходную
СФ автоматически.**

## Быстрый запуск и первая проверка

1. Скачать [архив проекта](https://github.com/malikvalikhodjaev/atb-ttn-autofiller/archive/refs/heads/main.zip),
   распаковать его, установить Python «3.10+» с [официального сайта](https://www.python.org/downloads/windows/)
   и открыть «start.cmd». Дополнительных библиотек не требуется.
2. В «Настройки подключения и справочники» сохранить «ИНН организации»,
   API-адреса, «project_code», «filial_id»; затем ввести доступы, проверить соединение,
   выбрать адрес погрузки и получить водителей из Smartup либо загрузить CSV.
3. Заполнить скачанный Excel-шаблон или получить список из Didox по фильтрам,
   выбрать одну СФ, нажать «Подготовить 1 СФ», проверить JSON и заполнить
   недостающие поля, отметить проверку и создать черновик; после проверки PDF
   повторить на двух–трёх СФ кнопкой «Подготовить выбранные СФ».

Краткий порядок: [RUNBOOK.txt](RUNBOOK.txt).
Настройки, доступы и ограничения: [INTEGRATION.md](INTEGRATION.md).
Карта полей: [HANDOFF.md](HANDOFF.md).
Формат входного списка: [README.txt](README.txt).

В окне доступны пустой Excel-шаблон и заполненный пример с тремя тестовыми
ID: в рабочем списке их нужно заменить реальными. Поиск Didox отбирает
исходящие СФ текущей организации по датам документа, ИНН покупателя и статусу,
по умолчанию «Подписан»; следующие страницы загружаются явно по «50» записей.
Выбранные СФ можно скачать в Excel, обработать одну либо несколько.

Список водителей можно получить из архивных заказов Smartup за «1–7» дней,
дополнить и сохранить прямо в окне, а также скачать CSV. Публичный API заказов
отдаёт ФИО и код машины; госномер, модель и ПИНФЛ берутся из сохранённого
справочника либо заполняются человеком. Полная таблица автомобилей конкретного
аккаунта может требовать дополнительного API, которого в общей документации нет.

## Проверка без реальных аккаунтов

```sh
python tools/demo_integration.py
```

Откроется отдельное окно «http://127.0.0.1:8766/», API-имитатор — на порту
«8767». В шапке написано «локальный имитатор»; реальные системы не вызываются,
реальные ключи ЭЦП в этом режиме не используются.

- Для одной СФ загрузить [examples/integration_one.csv](examples/integration_one.csv).
- Для трёх СФ загрузить [examples/integration_three.csv](examples/integration_three.csv).
- Подготовить, проверить и создать черновики: ожидается соответственно «1» или
  «3» записи со статусом «Черновик в Didox», относящиеся к имитатору.
- Повторное создание этих записей не создаёт новые документы.

Это проверка кода и интерфейса; она не подтверждает реальные права, поля,
ЭЦП и привязку к СФ. Для рабочего запуска нужен собственный список.
Для версии «0.2.0» прошли «63» автотеста; в браузере проверены одна СФ,
пакет из трёх СФ и повторное использование первого черновика без дубля.
[examples/sf_demo.csv](examples/sf_demo.csv) отдельно проверяет ошибки
и повторы входного файла, как описано в [examples/README.md](examples/README.md).

## Запуск из терминала

```sh
python app.py --check
python app.py
```

Сервер слушает только «127.0.0.1», обычно порт «8765». Если он занят, точный
свободный адрес печатается в консоли. Остановка: закрыть консоль или Ctrl+C.
Можно указать «--port», «--no-browser», «--config». В Windows доступен «check.cmd».

## Данные и повторы

«config.local.json» содержит параметры и частные справочники, исключён из Git.
Учётные данные вводятся в окне и остаются в памяти процесса; после перезапуска
нужен повторный вход. Ключ и пароль ЭЦП обрабатывает E-IMZO.

Результаты хранятся в «local-data/workflow.sqlite3». Сохраняйте эту папку при
обновлении и используйте один экземпляр программы для рабочего журнала.
Уже созданные записи не создаются повторно. Неопределённый результат после
обрыва соединения требует сверки с Didox, а не автоматического повтора.
Журнал содержит только документы этой установки; существующие ТТН проверяются
также по связям исходной СФ.

Исходный XLSX/CSV не изменяется. Изменения списка живут в странице до выгрузки;
подготовленные ТТН и результаты операций записываются в журнал.

## Проверка и сборка

```sh
python -m unittest discover -s tests -v
python tools/package_release.py
```

Архив кода и SHA-256 появятся в «dist». Настройки, журнал, рабочие документы,
ключи и исходная переписка в поставку не входят. Для запуска не нужны Node.js,
Codex и установка через pip.

| Файл | Назначение |
| --- | --- |
| «app.py» | Локальный HTTP API и диагностика |
| «invoice_processor.py» | XLSX/CSV, проверки, повторы и выгрузки |
| «settings.py» | Настройки и справочники, миграция схемы «1 → 2» |
| «connectors.py» | HTTP-клиенты Didox и Smartup |
| «workflow.py» | Подготовка, проверки, журнал SQLite, создание и подпись |
| «web/integration.js» | Аккаунты, предпросмотр, пакет, E-IMZO |
| «tools/demo_integration.py» | Локальная демонстрация одной/трёх СФ |
| «tests/test_integration.py» | Имитатор API и интеграционные тесты |

Если возник вопрос, технические детали можно уточнить по коду и официальным
API из «INTEGRATION.md»; доступы и неоднозначные исходные данные предоставляет
владелец аккаунтов.
