# Список СФ для подготовки ТТН

Локальное приложение «0.1.1» для загрузки списка счетов-фактур из Excel/CSV,
проверки реквизитов, исправления строк и сохранения результата.

**Интеграция с Didox и Smartup ещё не реализована. Создание, подписание
и отправка ТТН недоступны. Сохранение ссылок не подключает эти операции.**

## Короткая инструкция разработчику

1. Скачайте [архив проекта](https://github.com/malikvalikhodjaev/atb-ttn-autofiller/archive/refs/heads/main.zip),
   распакуйте его и запустите «start.cmd» с Python «3.10+» — порядок запуска
   описан в [коротком ранбуке](https://github.com/malikvalikhodjaev/atb-ttn-autofiller/blob/main/RUNBOOK.txt).
2. В разделе «Настройка при передаче» заполните «ссылки Didox/Smartup»,
   «ИНН организации» и «адрес погрузки».
3. По [заданию разработчику](https://github.com/malikvalikhodjaev/atb-ttn-autofiller/blob/main/HANDOFF.md)
   реализуйте авторизацию, получение данных и создание черновиков ТТН,
   проверьте одну СФ и затем добавьте пакетную обработку с действием
   «Подписать и отправить» через ЭЦП после проверки пользователем.

Для подключения без истории переписки начните с
[INTEGRATION.md](INTEGRATION.md): официальные API, необходимые доступы,
недостающие справочники и порядок реализации. Правила переноса полей
полностью собраны в [HANDOFF.md](HANDOFF.md).

Если что-то непонятно, технические детали можно решить самостоятельно по
[коду проекта](https://github.com/malikvalikhodjaev/atb-ttn-autofiller), а доступы,
недостающие данные и спорные правила заполнения — уточнить у заказчика.

## Локальный запуск

1. Установить Python «3.10» или новее с [официального сайта](https://www.python.org/downloads/windows/),
   распаковать весь проект. В установщике Windows включить доступ к Python
   из командной строки, если такая опция предлагается.
2. В Windows открыть «start.cmd». Дополнительных библиотек не требуется.
3. В окне раскрыть «Настройка при передаче», заполнить ссылки и реквизиты,
   сохранить. Можно сразу загрузить список СФ и проверить локальную обработку.

Короткая инструкция получателю: [RUNBOOK.txt](RUNBOOK.txt).
Задание для разработчика интеграции: [HANDOFF.md](HANDOFF.md).
Подробности формата входного файла: [README.txt](README.txt).

### Проверка за несколько минут

1. Запустить «check.cmd» либо «python app.py --check»: строки проверки
   Python, интерфейса и шаблона должны начинаться с «OK».
2. Открыть «start.cmd» и загрузить [examples/sf_demo.csv](examples/sf_demo.csv).
   Ожидается «4» строки: «2» проверены, «1» повтор, «1» требует исправления.
3. В строке «4» заменить «ИНН клиента» на «012345678» и нажать
   «Проверить изменения»: «3» проверены, «1» повтор, ошибок нет.
4. Сохранить отчёт и выбранный список XLSX, затем повторно загрузить XLSX:
   должны остаться «3» проверенные строки.

Все значения демонстрационные; существование этих СФ в Didox не предполагается.
Проверка работает без аккаунтов и внешних запросов. Подробности —
[examples/README.md](examples/README.md).

Из терминала на Windows, macOS или Linux:

```sh
python app.py --check
python app.py
```

Сервер слушает только «127.0.0.1». При занятом стандартном порте «8765»
выбирается свободный, адрес печатается в консоли. Закрытие консоли останавливает
программу. Исправления строк живут в памяти страницы до выгрузки.

## Настройки

Окно настройки сохраняет «config.local.json». Файл исключён из Git и архива
поставки. Можно создать его копированием «config.example.json». Он содержит
«didox_url», «smartup_url», «company_tin», «loading_address» и версию схемы.
Пароли, браузерные сессии и ключи ЭЦП в нём не хранятся.

«didox_url» и «smartup_url» — ссылки для открытия сайтов. «company_tin» и
«loading_address» сохраняются для будущего подключения. API-адреса, токены,
логины и права доступа нужно добавить при реализации интеграции; текущая
схема настроек отклоняет неизвестные поля.

Ссылки используются кнопками открытия сайтов; реквизиты сохраняются для
последующей интеграции. Приложение не проверяет доступность аккаунтов.

## Проверка и передача

```sh
python -m unittest discover -s tests -v
python tools/package_release.py
```

В «dist» появятся ZIP с исходным кодом и файл SHA-256. В ZIP включаются только
файлы из явного перечня: код, инструкции, тесты и пустой шаблон Excel.
Исходная переписка, рабочие списки СФ и локальные настройки туда не попадают.
Для запуска из архива Git, Node.js, Codex и установка через pip не нужны.

Если получен «ttn-processor-0.1.1.bundle», открыть Git-проект можно командой:

```sh
git clone ttn-processor-0.1.1.bundle ttn-processor
```
