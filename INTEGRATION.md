# Подключение Didox и Smartup — «0.2.0»

Код интеграции реализован: авторизация, поиск СФ, экспорт заказов, подготовка
ТТН, журнал, создание, PDF и отдельная подпись E-IMZO. Проверен на локальном
имитаторе; реальные аккаунты, обязательные поля и ЭЦП ещё нужно проверить.
Бизнес-правила и источники полей собраны в [HANDOFF.md](HANDOFF.md).

## Что получить у владельца аккаунтов

| Данные | Назначение |
| --- | --- |
| «ИНН организации», права Didox | Прочитать СФ, создать ТТН, подписать и отправить от нужной компании |
| «Партнёрский токен Didox» | Доступ к партнёрскому API |
| Пароль, пользовательский токен либо ЭЦП Didox | Вход; для физлица можно отдельно указать «ИНН/ПИНФЛ для входа» |
| API-сервер, логин/пароль Smartup | Доступ к архиву заказов |
| «project_code», «filial_id», при необходимости «filial_code» | Выбор нужной организации Smartup |
| Один адрес погрузки | Регион/район и адрес из справочника Didox; склад выбирается отдельно |
| Справочник водителей | «van_code», «vehicle_number», «vehicle_model», «driver_name», «driver_pinfl» |
| Адреса доставки, расстояния и веса | Используются из СФ/Smartup или заполняются при проверке ТТН |
| Одна реальная пара «СФ ↔ заказ» | Проверка даты, суммы с НДС, машины и водителя перед пакетом |

Токены/пароли вводятся в окне входа и не записываются в настройки/журнал.
ПИНФЛ и адреса справочников сохраняются в локальном «config.local.json»;
этот файл и «local-data/» исключены из Git и архива поставки.

## Первый вход

1. Запустить «start.cmd», открыть настройки и сохранить параметры организации.
   Предустановлены API-адреса «https://api-partners.didox.uz» и
   «https://smartup.online»; подтвердить рабочую среду у администраторов.
   «Ссылка Didox/Smartup» открывает сайт, а поле «API» задаёт сервер запросов.
2. Выбрать способ входа Didox: пароль, токен пользователя или E-IMZO.
   Для ЭЦП сначала загрузить ключи и выбрать ключ правильной организации.
3. Ввести логин/пароль Smartup и нажать «Войти и проверить доступы».
   Проверка Didox читает профиль, Smartup — архив за текущую дату.
   Пустой корректный ответ за сегодня допустим; нужную старую дату проверить
   на целевой СФ. Ошибка одной системы выводится отдельно.
4. После входа загрузить регионы/районы/склады, выбрать точку погрузки,
   сохранить настройки. Водителей можно получить из Smartup прямо в окне:
   выбрать «1–7» дней архивных заказов, получить ФИО/коды машин, заполнить
   недостающие госномер, модель и ПИНФЛ и сохранить таблицу. Сохранённые ранее
   данные подставляются; одинаковые ФИО/машина объединяются, новые строки
   добавляются к справочнику. Альтернатива — CSV по [шаблону](examples/drivers_template.csv).

Общий документированный API Smartup не предоставляет полного справочника
«водитель ↔ машина ↔ ПИНФЛ»: экспорт физических лиц не описывает ПИНФЛ и
привязку к автомобилю, поэтому его данные не угадываются и не выдаются за
полный список водителей. Получение списка здесь читает только архивные заказы
за выбранные дни. При недоступности одной даты список не сохраняется частично.

При истечении пользовательского токена нужно войти повторно. После смены
API-сервера, организации или параметров филиала старое соединение сбрасывается.

## Одна СФ, затем две–три

В окне скачать пустой XLSX-шаблон, заполнить своими ID и загрузить; рядом
можно скачать заполненный XLSX-пример с тремя тестовыми ID для имитатора.
В рабочем списке заменить их реальными. Вместо файла доступно получение
исходящих СФ текущей организации из Didox: даты документа, ИНН покупателя
(необязательно), статус (по умолчанию «Подписан»). Используются «owner=1»,
«doctype=001,002,008», «docDateFromCreated/ToCreated», «partner», «status».
Период — до года, по «50» СФ на страницу, дополнительные страницы добавляются
явно; после «2000» записей сузить фильтры. Результаты не отмечаются автоматически.
Выбранный список можно выгрузить в XLSX и использовать позднее.

В полученном списке выбрать одну проверенную строку и нажать
«Подготовить 1 СФ». Чтение СФ и Smartup ещё ничего не создаёт.

В найденной СФ сверяются дополнительные реквизиты списка и поставщик.
Заказ Smartup определяется по «person_tin», «delivery_date», «total_amount»
с суммой СФ с НДС, статус «A». Несколько совпадений требуют выбора заказа.

Проверить JSON и сообщения карточки. Из СФ копируются все позиции, исходные
цены, количества и суммы без НДС. Перерасчёта по округлённой цене нет.
Из Smartup берутся водитель и код автомобиля; номер, модель и ПИНФЛ берутся
из справочника по машине с проверкой ФИО. Несоответствие ФИО показывается.

Структурированный адрес доставки используется из «Buyer.DeliveryPoint» либо
из справочника «destinations» по ИНН покупателя; текст адреса — из СФ.
Если кодов региона/района нет, их нужно заполнить в JSON, а не угадывать.
Масса берётся из полей СФ; для единственной позиции возможен перенос общих
«total_weight_brutto/netto» заказа. Для нескольких позиций общая масса не
распределяется автоматически. Неизвестные веса не подменяются нулями.
Единицы массы проверить на реальном документе: преобразования единиц нет.

Расстояние задаётся по маршруту или в JSON «TotalDistance». Стоимость доставки
«DeliveryCost» и «TotalDeliveryCost» равна «0». После ручного заполнения нажать
«Проверить и сохранить JSON». Проверенные адрес, водитель и километры можно
сохранить отдельной кнопкой в справочники для следующей подготовки.

Перед созданием сверить официальный способ привязки к СФ, отметить проверку
и нажать «Создать выбранные черновики». Открыть PDF и проверить результат.
Для пакета загрузить две–три СФ, выбрать строки и нажать «Подготовить выбранные
СФ». Максимум «50» строк на запрос; интерфейс готовит группы до «5» и показывает
отдельный результат каждой строки. Ошибка одной СФ не отменяет успешные другие.

## Подпись

На компьютере подписанта должен работать E-IMZO. В окне загрузить ключи,
выбрать ключ и проверенные черновики, затем «Подписать и отправить выбранные».
Используется документ, повторно прочитанный из Didox, подпись через локальный
WebSocket E-IMZO, timestamp и отдельный запрос отправки. Если документ изменился
после подготовки подписи, отправка отклоняется. Подготовка подписи одноразовая,
действует «5» минут; пароль ключа приложение не получает.

Официальная инструкция [E-IMZO в Didox](https://api-docs.didox.uz/ru/integrators-eimzo).
Если локальный клиент не разрешает сайт или TLS-соединение, нужно настроить
его по официальной инструкции; отключение проверки сертификатов в коде
не используется. Доступность оферты и полномочий подписанта проверить в аккаунте.
Автоматического подписания оферты в приложении нет.

## Настройки и журнал

Полный перечень — [config.example.json](config.example.json); старая схема «1»
читается и переходит в «2». Настройки можно заполнить в окне, ключи API не
добавлять в поля ссылок. «loading_point» содержит «regionId», «regionName»,
«districtCode», «districtName», «address», необязательные махаллю и координаты.
«drivers» — массив водителей, «destinations» — адреса по ИНН покупателя,
«distances» — километры по ключу из региона/района/адреса погрузки и региона/района
доставки; удобнее сохранить значения из проверенной карточки.

Журнал «local-data/workflow.sqlite3» содержит исходные данные и состояния:
«needs_review», «ready», «creating», «uncertain», «draft», «signing»,
«sign_uncertain», «signed», «remote_document». Ключ — организация и ID СФ.
Повторный запуск с тем же журналом использует существующий результат.
Не удалять журнал ради повтора: сначала сверить документ с Didox.

При тайм-ауте/ошибке сервера после запроса создания результат может быть
неизвестен. Автоповтора записи нет; найти ТТН в Didox и сверить её ID в карточке.
Если документ точно не создан, пользователь может явно подтвердить это и
разрешить повтор. При неизвестном результате подписи сверить текущую ТТН.
После изменения настроек неподписанную подготовку нужно повторить либо
проверить и сохранить JSON заново. Перед обновлением сохранить настройки
и «local-data/». Работать с одним экземпляром программы на эту папку.

## Границы, которые проверить вживую

- Официальная привязка к существующей, особенно подписанной СФ: приложение
  хранит пару в журнале, но не меняет подписанную СФ и не отправляет выдуманный
  параметр связывания. Если требуется связь в интерфейсе Didox, её поддерживаемый
  способ нужно подтвердить до включения рабочего пакета.
- Реальные права, ветка организации, доступность архивной даты и API-лимиты.
- Соответствие «total_amount» сумме СФ с НДС, отсутствие нескольких совпадений.
- Коды адресов/упаковок, наличие ответственных лиц, веса и их единицы.
- E-IMZO, требования аккаунта к подписи и возвращаемые статусы.

Если API отклоняет конкретное поле, ошибка сохраняется по СФ. JSON можно
исправить до создания. Документы после создания исправляются в Didox;
автоматического изменения существующих СФ и подписанных ТТН нет.

## Официальные источники и код

Проверены «20.10.2026»: [авторизация Didox](https://api-docs.didox.uz/ru/home),
[документы Didox](https://api-docs.didox.uz/ru/integrators-documents),
[JSON типов документов](https://api-docs.didox.uz/ru/integrators-property-documents),
[Smartup API](https://api.greenwhite.uz/). В Smartup Basic Auth передаётся по HTTPS,
в Didox используются «Partner-Authorization» и «user-key».

«connectors.py» реализует эти HTTP-клиенты; TLS проверяется, редиректы с
учётными данными запрещены, запись не повторяется автоматически. «workflow.py»
проверяет совпадения и суммы, управляет журналом и отдельными операциями.
«app.py» предоставляет «/api/integration/connect», «prepare», «edit», «create»,
«jobs», «report», «pdf», «save-references», «reconcile», «sign-data», «sign».
Также доступны «search-invoices», «driver-candidates», «save-drivers» и
«GET /api/example» для заполненного демонстрационного XLSX.
Секреты не возвращаются через настройки или отчёты.

Проверка без аккаунтов: «python tools/demo_integration.py», список одной
или трёх СФ из «examples». Автотесты: «python -m unittest discover -s tests -v».
Демонстрационные API работают только на loopback; реальная ЭЦП в демонстрационном
интерфейсе отключена, серверный протокол подписи проверяется тестами.
